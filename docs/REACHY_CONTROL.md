# Play with Reachy Mini Control

Open the installed **Reachy Mini Control** app and start its local simulator. Then double-click **Play-Reachy-Control.cmd** in the game folder. This opens Echo Island connected to the app's localhost daemon on port 8000. Click Begin; fixed companion lines use the PC speaker and send antenna targets through the official SDK. Speaking is optional and the microphone is off by default; reply-complete and skip buttons are available.

The game launcher uses its own local controller on port 8768. It does not install Echo Island in the Control app's app catalogue: the game runs as a separate Godot window and communicates with the same robot daemon. You do not need to launch the game inside the app.

For a visible robot, the launcher also opens a **read-only MuJoCo view** using the official installed Reachy model. It displays the built-in mock simulator's live antenna and head motor positions; the game still controls the app's original daemon. The display settles the model's passive Stewart joints locally and sends nothing back. It is a visualization, not the source physics/control backend or evidence of physical calibration. It makes only local GET requests and closes if the source ceases to report running mock simulation. The app's own signaling/video connection is separate from the SDK state connection; a signaling error does not provide a 3D view. Close the MuJoCo window if you only want the game.

Simulation expressions now include gentle idle antenna sway and head turns, an attentive listening tilt, greeting waves, speech movement paced by the fixed WAV's loudness, a directional hint pose, and perked antenna cheers with small head bobs for every gem and the ending. Speech movement lasts for the whole clip. Simulation wakes smoothly from its measured parked pose, with bounded target speeds. Idle movement requires a live game heartbeat and stops during pause, narration, cancellation, disconnection and terminal stop. Hardware retains its original small antenna profiles; larger antenna and head expressions remain simulation-only until physical calibration.

The built-in **mock simulator** in the installed app reports daemon/SDK **1.14.0**. Its dedicated game adapter uses the app's matching Python/SDK environment without installing into or changing it. The adapter checks that the daemon is running, explicitly reports mock simulation, and matches the worker SDK version. Physical daemons are refused. This is the official SDK mock backend, distinct from both our old silent bridge fake and the separate MuJoCo physics viewer. The game labels it “REACHY MINI CONTROL / BUILT-IN SIMULATOR / NO HARDWARE”.

For the separately tested MuJoCo setup, use [Play-Reachy-Simulator.cmd](../Play-Reachy-Simulator.cmd) with its project-local SDK 1.12.0. Only one daemon can listen on port 8000: do not start the Control app's built-in mock daemon on top of MuJoCo. The Control launcher can also select an already running MuJoCo daemon, but it does not launch one itself.

Hardware uses separate Lite/Wireless adapters with explicit device setup. Selecting a real robot in Control does not automatically turn this simulator launcher into a hardware launcher. Physical validation remains pending.

Verification against the running Control app: seven native SDK/audio lifecycle checks passed using SDK 1.14.0, with 0.121 radians measured antenna excursion; see [lifecycle evidence](../artifacts/official-reachy/control-app-lifecycle.json). All **33 game-control assertions passed**, including actual SDK completion, pause, resume, repeat, skip, hints, narration handoff, connection recovery, emerald reward and stop, with zero technical-failure fallbacks; see [the Control app log](../artifacts/official-reachy/control-app-controls.log). Controller regressions run 83 tests with two optional live-Rasa skips. Tests use muted output and do not open the microphone. The restricted test environment could not write GStreamer's cache inside the app-owned environment; playback/EOS still passed. Godot's known certificate-store startup warning also remains unrelated to the loopback tests.
